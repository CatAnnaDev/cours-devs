# 06 — Le 2D

Un shader 2D n'est pas un shader 3D simplifié : c'est un **autre pipeline**, avec d'autres
entrées, d'autres contraintes, et d'autres solutions aux mêmes problèmes.

Ce chapitre dit ce qui change. Chaque leçon fournit ensuite ses deux versions :
`godot.gdshader` / `unity.shader` pour la 3D, `godot-2d.gdshader` / `unity-2d.shader` pour la 2D.

## Ce qui disparaît

| En 3D | En 2D |
|---|---|
| une **normale** par pixel | il n'y en a pas — la surface est plate |
| un **tampon de profondeur** | il n'y en a pas — l'ordre est décidé par le tri des calques |
| une **direction de vue** | la caméra regarde toujours tout droit |
| des **lumières** dans le calcul du matériau | seulement si tu actives un rendu 2D éclairé |
| l'**espace tangent** | pas de tangentes sur un quad de sprite |

Autrement dit : le fresnel (leçon 06), le triplanar (13), le parallax (14), l'écume par profondeur
(11) et les décalcomanies (16) n'ont **pas** d'équivalent direct. Quand une leçon a une version 2D,
elle utilise souvent une **autre technique pour obtenir le même résultat**.

Le meilleur exemple est le contour. En 3D, c'est le fresnel ou la coque inversée. En 2D, la seule
information de forme dont tu disposes est **le canal alpha** : on regarde si un pixel transparent a
un voisin opaque. Même besoin, mécanisme complètement différent.

## Ce qui apparaît

**Le canal alpha porte la forme.** C'est ta géométrie, ta silhouette, ton masque. Presque tous les
effets 2D partent de là.

**Tout est transparent.** Un sprite est dessiné en mélange alpha, donc tout ce que dit la leçon 07
sur le tri, l'overdraw et l'absence de test de profondeur anticipé s'applique **par défaut**, à
tout.

**L'atlas est partout.** Un sprite n'occupe presque jamais toute sa texture : c'est une région
d'une planche. Ça casse deux choses, et c'est le piège numéro un du 2D — voir plus bas.

## Godot

```glsl
shader_type canvas_item;

void fragment() {
    COLOR = texture(TEXTURE, UV) * COLOR;
}
```

Trois différences avec `spatial` :

**`COLOR` est en entrée **et** en sortie.** À l'entrée de `fragment()`, il contient déjà la couleur
de sommet et le `modulate` du nœud. Écrire `COLOR = texture(TEXTURE, UV)` **écrase** la teinte
choisie dans l'éditeur, et le nœud cesse de réagir à `modulate`. D'où la multiplication finale par
`COLOR`, qu'on retrouve dans tous les shaders 2D corrects.

**`TEXTURE` est fournie.** Pas besoin de déclarer un `sampler2D` : c'est la texture du nœud.

| Built-in | Contenu |
|---|---|
| `TEXTURE` | la texture du sprite |
| `TEXTURE_PIXEL_SIZE` | `1 / taille` en pixels — indispensable pour lire un voisin |
| `UV` | de 0 à 1 sur la **région** du sprite |
| `SCREEN_UV`, `SCREEN_PIXEL_SIZE` | pour lire l'écran |
| `VERTEX` | position 2D locale, dans `vertex()` |
| `COLOR` | modulate en entrée, couleur finale en sortie |

**Les `render_mode` utiles** : `blend_add` (magie, feu), `blend_mix` (défaut), `unshaded` (ignorer
les lumières 2D), `light_only`.

**Pour un effet plein écran**, mets le shader sur un `ColorRect` en `Full Rect` — c'est exactement
ce que font les bancs du cours.

## Unity URP 2D

C'est là que c'est le plus piégeux, parce qu'**URP a deux renderers**, et ils ne dessinent pas les
mêmes passes.

| Renderer | Passe attendue |
|---|---|
| Universal Renderer (3D) | `"LightMode" = "UniversalForward"` |
| 2D Renderer | `"LightMode" = "Universal2D"` |

Un shader qui n'a qu'une passe `UniversalForward` est **invisible** avec le 2D Renderer, et
inversement. Aucun message d'erreur : l'objet ne s'affiche simplement pas.

Les shaders 2D de ce cours déclarent donc **les deux passes**, avec le corps partagé dans un bloc
`HLSLINCLUDE` :

```hlsl
SubShader
{
    HLSLINCLUDE
    ... vert et frag, écrits une seule fois ...
    ENDHLSL

    Pass { Name "Sprite2D"  Tags { "LightMode" = "Universal2D" }      HLSLPROGRAM ... ENDHLSL }
    Pass { Name "SpriteFwd" Tags { "LightMode" = "UniversalForward" } HLSLPROGRAM ... ENDHLSL }
}
```

Chaque renderer prend la sienne, il n'y a jamais de double dessin, et le matériau marche dans les
deux projets. C'est deux passes de quatre lignes pour ne plus jamais se poser la question.

**Les autres réglages obligatoires d'un shader de sprite :**

```
Tags { "RenderType" = "Transparent" "Queue" = "Transparent" }
Blend SrcAlpha OneMinusSrcAlpha
ZWrite Off
Cull Off
```

Et la contrainte que tu as peut-être déjà rencontrée :

> `Material does not have a _MainTex or _BaseMap texture property.`

Un `SpriteRenderer` **exige** une propriété nommée exactement `_MainTex` ou `_BaseMap`. Tous les
shaders 2D du cours déclarent `_MainTex`.

Enfin, il faut lire la couleur de sommet — c'est elle qui porte la teinte du `SpriteRenderer` :

```hlsl
float4 color : COLOR;      // dans Attributes
...
return echantillon * IN.color;
```

## Unreal

Unreal fait de la 2D avec **Paper2D** (sprites) et **UMG** (interface), et les matériaux changent de
domaine :

| Usage | `Material Domain` |
|---|---|
| sprite Paper2D | `Surface`, `Shading Model: Unlit`, `Blend Mode: Translucent` |
| widget d'interface | **`User Interface`** |
| effet plein écran | `Post Process` |

Le domaine `User Interface` est le plus différent : il n'a que `Final Color` et `Opacity`, et les
coordonnées sont celles du widget.

## Le piège numéro un : l'atlas

Un sprite dans une planche occupe une région, disons de `(0.25, 0.5)` à `(0.375, 0.625)`. Deux
choses cassent aussitôt.

**Le carrelage est impossible.** Multiplier l'UV par 4 sort de la région et va lire le sprite du
voisin. Il n'y a pas de contournement propre : soit la texture est **hors atlas**, soit tu
transportes les bornes de la région dans le shader pour y ramener l'UV toi-même.

**Lire un voisin déborde.** Tous les effets qui échantillonnent autour du pixel — contour,
flou, détection de bord — vont chercher **dans le sprite d'à côté** dès qu'ils touchent la
frontière de la région.

Les parades, par ordre de simplicité :

1. **Sortir la texture de l'atlas.** En Godot, décocher l'inclusion dans l'atlas ; en Unity, mettre
   le sprite en `Sprite Mode: Single` hors Sprite Atlas.
2. **Ajouter une marge transparente** autour de chaque sprite dans la planche — quelques pixels
   suffisent pour un contour, et ça règle aussi le débordement du filtrage bilinéaire.
3. **Transporter la région** en uniforme et clamper les lectures.

C'est la source de « ça marche en test et pas dans le jeu » la plus fréquente en 2D, parce que les
atlas sont souvent générés **à la construction** et pas pendant le développement.

## Le pixel art

Trois règles, et elles se contredisent avec le reste :

**Filtrage `Nearest`, toujours.** Le bilinéaire floute et détruit le style.

**Pas de mipmaps.** Elles mélangent les pixels voisins.

**Attention aux effets qui supposent du continu.** Un contour d'un pixel sur du pixel art
affiché à ×4 fait un contour de quatre pixels écran — souvent voulu. Mais un `smoothstep` produit
des demi-teintes qui n'existent pas dans ta palette.

Pour du pixel art, `step` franc plutôt que `smoothstep`, et une quantification finale sur la
palette (leçon 08 en 2D).

## Ce que ça coûte

Le 2D est bien moins cher en calcul, et **bien plus exposé à l'overdraw**.

Un décor 2D, ce sont des dizaines de calques translucides empilés : ciel, arrière-plan lointain,
proche, décor, personnages, effets, interface. Chaque pixel de l'écran est écrit dix ou vingt
fois, et **aucun test de profondeur anticipé** ne peut l'éviter puisque tout est transparent.

Les trois optimisations qui comptent, dans l'ordre :

1. **Découper les quads au plus près de la forme.** Un sprite dont 70 % est transparent coûte
   quand même 100 %. Godot et Unity savent générer une géométrie ajustée à l'alpha.
2. **Marquer opaques les sprites qui le sont.** Un fond plein n'a aucune raison d'être en mélange
   alpha.
3. **Regarder la vue Overdraw.** Godot : `Debug` → `View Overdraw`. Unity : mode `Overdraw` de la
   vue Scene. Une fois suffit à changer la façon dont on empile les calques.

## À retenir

1. Pas de normale, pas de profondeur : **l'alpha porte la forme**.
2. En Godot, multiplie toujours par `COLOR` à la fin, sinon `modulate` ne marche plus.
3. En Unity, déclare **les deux passes** `Universal2D` et `UniversalForward`, et nomme la texture
   `_MainTex`.
4. Un atlas casse le carrelage et la lecture des voisins. Marge transparente, ou hors atlas.
5. Pixel art : `Nearest`, pas de mipmaps, `step` plutôt que `smoothstep`.
6. Le coût du 2D, c'est l'overdraw.
